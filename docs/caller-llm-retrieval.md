# MCP 호출 LLM이 판단하도록 검색 계약 전환

2026-09-06 작업 기록입니다. 변경 전 작업 트리에는 2차 개선사항이 이미 있었으며,
이번 비교는 그 상태를 기준으로 합니다. 이 문서의 수치는 검색 근거 접근성입니다.
실제 LLM의 최종 답변 정답률은 아직 측정하지 않았습니다.

재현에 사용하는 corpus는 [krx-rule-markdown `8b8d951`](https://github.com/chromato99/krx-rule-markdown/commit/8b8d951f2d722c922fbbbd49d2ea4f532edbdbdc)입니다.
수동 검색 평가 workflow의 `corpus_ref`에는 `8b8d951f2d722c922fbbbd49d2ea4f532edbdbdc`를 지정합니다.

## 변경한 동작

- `search_rules`에서 `answerable`과 `answerability`를 제거했습니다.
  `contract_version: retrieval-v1`, `retrieval.status`, `retrieval.returned_results`와
  제한된 검색 결과를 제공합니다. 상태는 `candidates_found` 또는 `no_candidates`입니다.
- 의미상 근거 부족·모호함을 판정해 결과를 비우거나 다른 결과로 교체하던 로직과
  답변 판정 전용 수치·주체·예외·조건 규칙, 기한 충돌 탐색을 제거했습니다.
  검색에 쓰이는 용어 추출, 숫자 경계, 문서/시장 순위 신호는 유지했습니다.
- 잘못된 전제가 있는 질문에도 검토할 후보를 전달합니다. 질문의 전제를 반박하는
  조문인지, 다른 시장의 근거인지, 근거 자체가 부족한지는 호출 LLM이 판단합니다.
  명시적 필터, 출처·조문·첨부 연결, 변환 품질 안내와 출력 제한은 유지합니다.
- 불일치하거나 없는 인덱스는 MCP tool error로 처리합니다. 필수 embedding/reranker
  실패 역시 오류입니다. 이런 운영 실패를 의미상 근거 부족으로 처리하지 않습니다.
- initialize 지침과 tool 설명에 문맥 조회, 조건·예외·주체 확인, 추가 검색과 재질문
  책임을 명시했습니다. 동일한 도구 JSON을 text content에도 제공해 모델 호스트가
  내용을 읽을 수 있게 했습니다. 전체 HTTP 응답 크기 제한은 그대로 적용합니다.
- 선택형 reranker의 실행·채택 조건에서 `supported` 판정을 제거했습니다.
  활성화된 한국어 reranker는 제한된 후보를 재정렬합니다. 기본값은 계속 꺼져 있고,
  이번 corpus 비교에서도 사용하지 않았습니다.

[LLM 클라이언트 안내](llm-client.md)에 응답 마이그레이션과 모델 지침 예시를
정리했습니다. 이전 `answerable` 필드에 의존한 클라이언트는 수정이 필요합니다.

## 같은 지표로 비교한 결과

변경 전에 210건과 38건의 실제 MCP 서비스 검색 응답 및 조회 문맥을 저장했습니다.
이전 판정 상태는 검색 상태로 투영하고, 후보를 추가·삭제하지 않은 채 새 평가기로
다시 측정했습니다. 질문뿐 아니라 언어·필터·limit까지 같은 입력을 대응시켰습니다.
따라서 과거의 ‘선택한 답변 근거 정밀도’와 새 ‘검색 근거 포함률’을 혼동하지 않습니다.

| 검증 자료 | 문서 Hit@5 변경 전 → 후 | 근거 묶음 Hit@5 변경 전 → 후 |
|---|---:|---:|
| 기존 210문항 | 149/150 → 150/150 | 140/142 → 141/142 |
| 기존 38문항 | 18/27 → 26/27 | 16/27 → 23/27 |

38문항 중 답변 가능한 27문항에서 문서 포함률은 66.67%에서 96.30%로,
필요한 근거 묶음 포함률은 59.26%에서 85.19%로 높아졌습니다. 근거를 볼 수 있게 된
질문이 7개 늘었고, 기존에 충족하던 질문의 근거 포함 실패는 추가되지 않았습니다.
210문항에서도 문서·근거 포함의 개별 질문 회귀는 없었습니다.

210문항의 근거 포함은 한국어 113/114, 영어 26/26, 언어 미지정 2/2입니다.
38문항에서는 한국어 21/24, 영어 2/3입니다. 이 수치는 상위 5개 결과와 그 결과에
연결된 청크 문맥을 검사합니다. 모델이 자동으로 올바른 답을 만든다는 뜻은 아닙니다.
두 평가에서 필터 누출은 0건이고 조회 문맥의 소유 관계 일치는 100%였습니다.

기존 210문항에는 문서 수준 기대값만 있는 8문항이 있어 문서 지표 분모는 150,
근거 지표 분모는 142입니다. 범위 밖·모호한 질문은 최종 답변 성공의 분모에 넣지
않습니다. 후보가 반환되었다는 이유로 답변을 승인하거나 거절 성공으로 세지 않습니다.

## 남은 한계

38문항의 근거 미충족 4건은 다음과 같습니다. 문서가 검색돼도 현재 반환 문맥에
필수 내용이 모이지 않는 경우가 포함됩니다. 원문 추가 조회로 해결되는지는
실제 호출 LLM 평가에서 확인해야 합니다.

| 질문 ID | 남은 문제 |
|---|---|
| `scope-03` | 영문 분쟁조정 시행세칙의 여러 별지 서식: 기대 문서가 반환되지 않음 |
| `scope-14` | 장외파생공동기금의 규제자본 변수 제공 목적·대상: 문서는 있으나 필수 근거 미충족 |
| `scope-17` | 배출권 분쟁조정의 공개 여부와 비밀유지: 문서는 있으나 필수 근거 미충족 |
| `scope-22` | 코스닥 글로벌 기업 지정의 심사·통보·지정 시점: 문서는 있으나 복수 조건 미충족 |

210문항에는 분쟁조정 기록 보관기간 질문 `audit-e-dispute-record-retention`의
근거 미충족이 남았습니다. 이 질문들을 맞추기 위한 별칭이나 순위 예외는 추가하지
않았습니다. 문서·질의·target·사전·embedding 모델·corpus/index는 이번 작업에서
바꾸지 않았습니다. 두 자료 모두 이미 검토한 검증 세트이며 독립 출시 증거가 아닙니다. 38문항의
질문·target은 보존하고 lifecycle만 development/validation으로 변경했습니다.
변경 전 fixture 원본은 실험 디렉터리에 별도로 보관합니다.

과거 95% 정밀도·90% 답변 coverage 게이트의 실패는 [2차 기록](rag-improvement-cycle-2.md)에
그대로 남깁니다. 새 게이트 통과는 서버 검색 회귀가 없다는 뜻입니다. LLM 제품의
정답률·잘못된 단정·재질문·비용·지연은 별도 목표와 독립 자료로 검증해야 합니다.

평가 결과를 점검하면서 기존 집계기가 `validation` split을 전체/언어별 요약에서
누락하던 문제도 수정했습니다. 전체 지표의 분모는 유지하며 검증 세트별 결과를
보고서와 CI 요약에서 확인할 수 있습니다.

## 구현 검증과 재현

- 전체 Go 테스트, `go test -race ./...`, `go vet ./...` 통과.
- 문맥 없는 후보, 잘못된 전제, 모호한 범위, 기본/1/5/50 반환 제한과 명시적 필터 검증.
- 잘못된 문서/조문/첨부/source, 중복·누락·잘린 청크, 여섯 번째 문서의 근거를
  상위 5개 성공으로 세는 오류를 검출하는 평가 테스트 통과.
- 고정 full-vector 인덱스로 210문항 검색 회귀 게이트 통과 및 38문항 재측정.
- 임시 localhost HTTP 서버에 실제 MCP SDK로 initialize/search/get_context 호출,
  한국어·영어 검색, 기본/1/5/50 제한과 readiness 검증. 사용한 임시 서버는 종료.

현재 비교 기준선은 `eval/baselines/rag-retrieval-before.json`입니다. 원시 보고서는
`eval/results/caller-llm/`의 `rag-v1-before.json`, `rag-v1-after.json`,
`rag-holdout-scope-20260906-before.json`, `rag-holdout-scope-20260906-after.json`에
있습니다. 변경 전 응답 재생 시간은 실제 검색 지연이 아니므로 지연 개선율을
계산하지 않습니다. 식별자와 해시는
[실험 provenance](../eval/experiments/20260906-caller-contract/provenance.json)에 기록합니다.

```bash
python3 eval/compare.py \
  eval/results/caller-llm/rag-v1-before.json \
  eval/results/caller-llm/rag-v1-after.json
```

위 수치는 커밋 전 고정한 코드에서 측정했고, 게시 커밋과의 코드 해시 일치를 확인합니다.
실제 답변 생성 LLM의 최종 평가와 운영 배포는 수행하지 않았습니다. 커밋과 원격 CI
상태는 PR 후속 코멘트에서 확인할 수 있습니다. 원시 보고서와 변경 전 응답·소스는
[평가 아카이브](../eval/archives/README.md)에 보관합니다.
